## 1. 结论

ArceOS 当前没有统一的 UART 驱动层。应用看到的是 `axhal::console` 字节流接口，实际后端由 `axplat` 的编译期 `ConsoleIf` 实现决定：

- `riscv64-qemu-virt` 使用 SBI Debug Console（DBCN），不直接访问 QEMU virt 的 16550 MMIO UART。
- `x86_64` 平台使用 crates.io 的 `uart_16550 0.4.0`，由 `SpinNoIrq<SerialPort>` 串行化同步 PIO 收发。
- 输入的“阻塞”由 `axstd`/POSIX 层反复非阻塞读取并 `yield_now` 实现，不是设备中断唤醒。
- RISC-V 平台虽声明了 UART `0x1000_0000` 和 PLIC `0x0c00_0000` MMIO 区间，但 PLIC claim/complete、IRQ enable 均未实现，当前无法分派 UART 外部中断。

因此，`riscv64-qemu-virt` 上的异步串口改造首先是平台中断能力建设，其次才是 UART Future 接口接入。

## 2. 分层与调用路径

### 2.1 输出路径

```text
application: axstd::print!/stdout.write
    -> arceos_api::stdio::ax_console_write_bytes
    -> axhal::console::write_bytes
    -> axplat::ConsoleIf (compile-time implementation)
       -> RISC-V: SBI console_write
       -> x86_64: SpinNoIrq<uart_16550::SerialPort>::send
```

`axlog` 也最终调用 `axhal::console::write_bytes`。`axplat` 在接口层提供全局 `CONSOLE_LOCK: SpinNoIrq<()>` 防止日志交错；x86 后端内部还有 `COM1` 锁。所有路径都是同步写入，`flush()` 在 stdio 层为空操作。

### 2.2 输入路径

```text
shell / axstd::io::stdin
    -> StdinRaw::read
    -> arceos_api::stdio::ax_console_read_bytes
    -> axhal::console::read_bytes
    -> axplat::ConsoleIf
       -> RISC-V: SBI console_read
       -> x86_64: SerialPort::try_receive

无数据:
    -> 返回 0
    -> Stdin::read 循环重试
    -> thread::yield_now / sys_sched_yield
```

该模型避免纯自旋占满 CPU，但每次调度后仍主动轮询设备。POSIX `FileLike::poll()` 对 stdin 固定返回 `readable: true`，不能表达真实 UART 就绪状态；C `poll(2)` 当前也仍是 `unimplemented()`。

### 2.3 换行与缓冲

- `arceos_api` 和 POSIX stdio 都把输入 `\r` 转换为 `\n`。
- `BufReader<StdinRaw>` 提供行读取缓存，设备层本身没有 RX ring buffer。
- x86 `read_bytes` 会持续读取到目标缓冲区满或 UART 暂时无数据。
- RISC-V SBI 每次最多传输 256 字节，输出先复制到内核栈缓冲区再转换为物理地址。

## 3. 启动和所有权

`axruntime::rust_main` 的关键顺序是：

```text
axhal::init_percpu
  -> axhal::init_early             # trap/time，early console 已可用
  -> 输出 Logo、初始化日志和内存
  -> axhal::init_later             # CPU IRQ bits/time
  -> axtask::init_scheduler
  -> axdriver::init_drivers        # 仅 fs/net/display feature 路径
  -> init_interrupt               # timer 等静态 handler
  -> application main
```

当前 console 归 platform crate 所有，不经过 `axdriver::init_drivers()`。`ConsoleIf` 是 `axplat` 的编译期接口，不提供运行时替换 console 的注册 API。这意味着“保留 SBI early console，启动后切换 UART”需要平台实现内部增加状态分派，或先将异步 UART 作为独立设备暴露而不替换系统 console。

## 4. 中断路径现状

`modules/axhal/src/irq.rs` 只做统一转发：trap handler 在 `NoPreempt` guard 下调用 `axplat::irq::handle(vector)`。设备 IRQ 的实际注册、屏蔽、claim 和 complete 均属于平台 crate。

RISC-V QEMU virt 0.4.1 平台当前状态：

| 能力 | 状态 | 影响 |
|------|------|------|
| `sie` 软件/时钟/外部中断位 | 已启用 | CPU 可接收 supervisor external interrupt |
| handler table | 已存在 | 可按设备 IRQ 保存 handler |
| PLIC source enable/disable | TODO | `set_enable()` 只打印 warning |
| PLIC claim | TODO | external interrupt 固定调用 `handle(0)` |
| PLIC complete | TODO | 无法正确完成设备中断 |
| UART IRQ 常量 | 未配置 | 需要补 UART0 IRQ（QEMU virt 通常为 10）并以平台配置为准 |

仅调用 `axhal::irq::register(UART_IRQ, handler)` 不会让 UART 中断工作。必须先完成 PLIC context、priority、enable、threshold、claim/complete 的平台实现。

## 5. 对异步集成的约束

### 5.1 必须保留 early console

early boot 发生在 allocator、scheduler 和通用 IRQ 初始化之前。异步 UART 依赖静态缓冲、任务执行和中断，不能承担 panic/early boot 的唯一输出路径。RISC-V 应保留 SBI console，至少直到异步 UART 完成初始化；更稳妥的设计是始终保留 SBI 作为故障回退。

### 5.2 `axtask` 不是 Future executor

`axtask::spawn`/`spawn_raw` 接受 `FnOnce()`，仓库内没有通用 `Future` executor、`RawWaker` 或 `block_on(Future)`。已有名为 `block_on` 的网络函数只是 `WouldBlock + yield_now` 循环。异步 UART 的 `OsRuntime::spawn(Future)` 不能直接映射到现有 API，需新增最小 executor adapter 或先补通用内核 Future 执行器。

### 5.3 同步 API 不能直接获得异步语义

即使 RX 数据由中断填入 ring buffer，现有 stdin 仍会 `read -> 0 -> yield -> retry`。若目标是消除轮询，还需让 stdio/FD 层能够：

1. 在 ring buffer 空时挂起当前任务或返回 `WouldBlock`；
2. 在 ISR/bottom-half 收到数据后唤醒等待任务；
3. 让 `poll()` 根据 ring buffer 状态报告 readiness。

第一阶段可保持现有同步 API 兼容，仅替换其数据源；真正的 async API 应作为后续独立接口落地。

## 6. 建议边界

| 层 | 建议职责 |
|----|----------|
| `axplat-riscv64-qemu-virt` | PLIC、UART MMIO/IRQ 常量、early SBI console、设备 IRQ 分派 |
| `uart_16550` | 寄存器、ISR 最小动作、ring buffer、copier Future、async reader/writer |
| ArceOS adapter（建议独立模块/crate） | 实现 runtime/waker/lock/MMIO/IRQ 适配，管理静态实例和 IRQ trampoline |
| `axhal::console` | 保持稳定的同步 early/diagnostic console 接口 |
| `arceos_api` / `axstd` | 同步兼容 API、readiness、未来的 async stdio API |

不建议直接把 Future executor 或 UART 设备状态塞入 `axhal::console`。平台中断、驱动机制、OS 调度适配应保持可独立验证。
