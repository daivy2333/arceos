## 1. 结论

M3 已具备实施条件：M1 已打通 RISC-V PLIC/IRQ 10，M2 已提供真正阻塞的单 Future `block_on`。最短路径是在新建的 `examples/async_uart` 内完成独立 late-device PoC：保留 SBI console，初始化 MMIO UART，创建静态 RX/TX ring，注册无参 IRQ trampoline，启动两个 copier task，再运行单 reader/单 writer echo Future。

M3 不接入 TTY、stdin/stdout、POSIX readiness 或 `axdriver` 通用设备模型。这些属于 M5/M6。M3 的验收闭环是：

```text
host input -> UART IRQ 10 -> fn() trampoline -> uart_16550 ISR
  -> RX copier -> RX ring -> echo Future -> TX ring -> TX copier -> host output
```

## 2. 已解锁能力与真实缺口

| 能力 | 当前状态 | M3 动作 |
|------|----------|---------|
| PLIC claim/complete、source enable | M1 已完成 | 复用 `axhal::irq::{register, set_enable}` |
| Future Pending 阻塞与 wake | M2 已完成 | 使用公开路径 `axtask::block_on` |
| task spawn | 已有 `axtask::spawn_raw` | 闭包内执行 `block_on(future)` |
| UART IRQ 基线 | `examples/uart_irq` 已验证 | 复用 base、stride=1、IRQ=10 和初始化顺序 |
| async UART 核心 | `../uart_16550` 已有 | path dependency + `async` feature |
| ArceOS adapter/bootstrap | 缺失 | M3 主要实现工作 |
| 等待式 async read/write | 驱动尚未提供 | example 内用 ring poll Future 桥接 |

当前 `axtask::future` 是私有模块，仅将函数 re-export 到 crate 根。StarryOS 的 `axtask::future::block_on` 不能原样复制，应使用 `axtask::block_on`。

## 4. Adapter 设计

### 4.1 Runtime 与 WakerSet

`ArceOsRuntime::spawn` 映射为：

```text
axtask::spawn_raw(
  move || axtask::block_on(future),
  name.into(),
  axconfig::TASK_STACK_SIZE)
```

每个 RX/TX copier 占一个内核任务，不引入通用多 Future executor。

M3 只有一个 RX echo consumer 和一个 TX copier waiter，可实现 IRQ-safe 单槽 `OsWakerSet`：`register` 保存/更新 waker，`wake` 取出并唤醒，返回 0/1。实现必须写明它不是通用 multi-waker `PollSet`；若实测同一 ring 需要两个不同 waiter，应改为有界集合而不是静默覆盖。

### 4.2 UART 所有权与 ISR

```text
SpinNoIrq<Uart16550<MmioBackend>>  # 唯一寄存器访问对象
ArceOsUartPort                     # &'static SpinNoIrq<...>
AtomicU8 CACHED_IER                # ISR/copier 回调共享
Once<Arc<AsyncUartDriver<...>>>    # driver 固定到内核退出
static mut RX_BUF/TX_BUF           # bootstrap 单次初始化
```

ArceOS handler 类型是 `fn()`，因此 trampoline 固定绑定 IRQ 10、MMIO VA 和 `CACHED_IER`，再调用 `uart_isr_handler(10, base, &CACHED_IER)`。不回移 StarryOS 全局 IRQ hook。

### 4.3 初始化顺序

1. 解析 UART MMIO VA，构造并初始化同步 UART；
2. 初始化 RX/TX ring backing storage；
3. 创建并发布 UART port 与 driver；
4. 注册 IRQ 10 trampoline；
5. 启动 RX/TX copier tasks；
6. 开启 PLIC source；
7. 最后写 UART IER，开启 RX DATA_READY；
8. 启动 echo Future。

不变量是：任何设备 IRQ 到达时，driver、copier waker 和 trampoline 上下文均已发布。early/panic 日志始终走 SBI。

## 5. Echo Future 的等待语义

当前 `embedded_io_async::Read` 空 RX 会返回 `Ok(0)`，`Write` 允许短写，`flush` 立即返回，不能直接用于等待式 echo。M3 应围绕公开 ring API 构造局部 Future。

RX：

```text
pop -> 有数据则 Ready
    -> 无数据则 register(waker) -> 再 pop
    -> 有数据 Ready，否则 Pending
```

TX：

```text
push -> 有空间则 Ready(n)
     -> 无空间则 register(waker) -> 再 push
     -> 有空间 Ready(n)，否则 Pending
```

echo task 循环处理短写，直到当前 RX batch 全部进入 TX ring。它是 RX ring 唯一 consumer 和 TX ring 唯一 producer，从而满足当前 SPSC 安全前提。

## 6. 风险与隔离

| 风险 | M3 处理 | 后续归属 |
|------|---------|----------|
| TX copier 暂满时可能立即重 poll | Gate 观察 busy-loop；复现则作为 M3 blocker 最小修复 | M3/M6 |
| RX ring 满时可能丢数据 | M3 只验证有界 payload | M4/M6 |
| 全局 AtomicWaker 只支持单 port | 限定单 UART | M6 |
| IER RMW 有 SMP 竞态 | M3 只声明 SMP=1 | M6 |
| async read/write 契约不完整 | example 局部桥接 | M6 |

## 7. 验收 Gate

### Build

- riscv64 release build 通过，启动日志保留 SBI；
- 依赖解析到本地 `uart_16550 0.6.0`；
- 没有 `axpoll`、TTY、VFS、POSIX 新依赖。

### Functional

- 1B、64B、4KiB 输入按原顺序完整 echo；
- 日志/计数证明 IRQ、RX copier、echo、TX copier 均发生；
- handler 返回后无 IRQ storm。

### Scheduler/Idle

- 无输入时 echo、RX copier、TX copier 均 Pending/Blocked；
- wake 后恢复，不依赖 `yield_now` 轮询；
- 10 分钟与 20 次启动仍留给 M4。

### Rollback

- 删除 M3 workspace member/example 即可回退；
- M1 platform、M2 block_on、`examples/uart_irq` 不修改；
- SBI console 行为不变。
